# Порівняння Naive RAG та Sentence-Window Retrieval

Цей звіт порівнює дві різні стратегії Retrieval-Augmented Generation (RAG): Naive RAG та Sentence-Window Retrieval. RAG-системи поєднують великі мовні моделі (LLM) із зовнішніми джерелами знань для підвищення точності та актуальності згенерованих відповідей.

## Naive RAG (Наївний RAG)

**Naive RAG** є найпростішою формою RAG. У ньому система отримує відповідну інформацію з бази знань і безпосередньо передає її LLM для генерації відповіді.

### Як працює Naive RAG:

1.  **Індексація:** Вихідні дані (наприклад, PDF-файли, HTML, текстові документи) очищаються, витягуються та перетворюються на єдиний текстовий формат. Потім ці дані розбиваються на менші *чанки* (блоки тексту), які потім перетворюються на векторні представлення (ембеддінги) та зберігаються у векторній базі даних.
2.  **Отримання (Retrieval):** Коли користувач надсилає запит, він також перетворюється на векторне представлення. Система обчислює бали подібності між вектором запиту та векторами чанків у базі даних, а потім вибирає `k` найбільш релевантних чанків.
3.  **Збільшення (Augmentation):** Отримані чанки об'єднуються із запитом користувача, формуючи розширений контекст для LLM.
4.  **Генерація (Generation):** LLM використовує цей розширений контекст для створення відповіді на запит користувача.

### Переваги Naive RAG:

*   **Простота впровадження:** Легко налаштовується, оскільки безпосередньо інтегрує отримання інформації з генерацією.
*   **Не потребує донавчання (Fine-tuning):** Немає необхідності донавчати LLM, що економить час та ресурси.
*   **Підвищена точність:** Використання зовнішньої, актуальної інформації значно покращує точність генерованого контенту порівняно з автономними LLM.

### Обмеження Naive RAG:

*   **Проблема розміру чанків:** Розмір чанка є компромісом. Менші чанки забезпечують краще зіставлення подібності, але можуть втратити навколишній контекст. Більші чанки надають більше контексту для LLM, але ембеддінги можуть стати "розмитими", що ускладнює точне отримання.
*   **Схильність до галюцинацій:** Якщо отриманий контекст недостатній або нерелевантний, LLM може все одно генерувати неточні або вигадані відповіді.

## Sentence-Window Retrieval (Отримання за вікном речень)

**Sentence-Window Retrieval** — це просунута техніка RAG, розроблена для покращення контексту, що надається LLM під час виведення. Вона вирішує проблеми з розміром чанків, властиві Naive RAG.

### Як працює Sentence-Window Retrieval:

1.  **Індексація:** Великі текстові документи сегментуються на окремі речення, які виступають як одиниці (чанки) для отримання. Кожен вузол представляє одне речення.
2.  **Отримання та розширення вікна:** Коли надходить запит користувача, система спочатку отримує найбільш схоже речення (фокусне речення) з векторної бази даних. Потім система розширює цей контекст, витягуючи "вікно" з кількох сусідніх речень (до і після фокусного речення) як метадані.
3.  **Генерація:** LLM отримує фокусне речення разом із цим розширеним "вікном" сусідніх речень, що забезпечує більш багатий та повний контекст для генерації відповіді.

Параметр "розмір вікна" визначає кількість сусідніх речень, що витягуються. Більший розмір вікна захоплює більше контексту, але занадто велике вікно може знизити продуктивність RAG-системи.

### Переваги Sentence-Window Retrieval:

*   **Покращена релевантність відповіді та обґрунтованість:** Дослідження показують значні покращення в цих метриках порівняно з базовим RAG, оскільки LLM отримує більш цілеспрямований та водночас широкий контекст.
*   **Висока точність отримання:** Використання речень для початкового отримання зберігає ембеддінги сфокусованими, що призводить до кращого зіставлення подібності.
*   **Багатий контекст для LLM:** Вікно навколишніх речень гарантує, що LLM має достатньо контекстної інформації для генерації послідовних і точних відповідей.
*   **Зменшення кількості токенів:** Завдяки більш цілеспрямованому контексту, це може призвести до більш лаконічних відповідей.

## Порівняння Naive RAG та Sentence-Window Retrieval

| Характеристика          | Naive RAG                                            | Sentence-Window Retrieval                                   |
| :---------------------- | :--------------------------------------------------- | :---------------------------------------------------------- |
| **Стратегія чанкування** | Фіксовані чанки для отримання та синтезу.          | Малі чанки (речення) для отримання; більший контекст (речення + вікно) для синтезу. |
| **Контекст для LLM**    | Безпосередньо отриманий чанк.                        | Отримане речення плюс конфігуроване вікно навколишніх речень. |
| **Точність отримання**  | Може бути скомпрометована більшими розмірами чанків. | Покращена завдяки використанню гранулярності на рівні речень для початкового отримання. |
| **Багатство контексту** | Обмежене одним отриманим чанком.                    | Багатше завдяки вікну навколишніх речень.                    |
| **Галюцинації**         | Більш схильний, якщо контекст недостатній або шумний. | Менш схильний завдяки більш цільовому та всебічному контексту. |
| **Складність**          | Простіший у реалізації.                             | Більш просунутий, передбачає додаткову обробку для формування вікна. |
| **Продуктивність**      | Базовий рівень.                                      | Демонструє покращення релевантності відповіді та обґрунтованості.

## Висновок

Naive RAG є простою відправною точкою для впровадження RAG-систем, але його продуктивність може бути обмежена через компроміси у розмірі чанків. Sentence-Window Retrieval пропонує більш складний підхід, який дозволяє отримати кращий баланс між точністю отримання та повнотою контексту для LLM, що призводить до більш релевантних, обґрунтованих та менш "галюцинаційних" відповідей. Це робить Sentence-Window Retrieval кращим вибором для сценаріїв, де висока якість відповіді є критично важливою.

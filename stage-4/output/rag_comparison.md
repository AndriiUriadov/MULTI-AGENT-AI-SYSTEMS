# Порівняння Naive RAG та Sentence-Window Retrieval

Цей звіт порівнює два підходи до Retrieval-Augmented Generation (RAG): Naive RAG та Sentence-Window Retrieval.

## Naive RAG

Naive RAG є найпростішою формою RAG. Його основна ідея полягає в наступному:
1.  **Розбиття документа**: Документи розбиваються на менші, фіксовані за розміром частини (чанки), часто за кількістю символів.
2.  **Вбудовування**: Як чанки, так і запити користувачів перетворюються на числові вектори (вбудовування) за допомогою моделі вбудовування.
3.  **Векторна база даних**: Вектори чанків зберігаються у векторній базі даних.
4.  **Отримання**: Під час запиту система шукає у векторній базі даних найбільш релевантні чанки, порівнюючи вбудовування запиту з вбудовуваннями чанків.
5.  **Генерація LLM**: Отримані чанки безпосередньо передаються Великій Мовній Моделі (LLM) разом із запитом користувача для генерації відповіді.

**Переваги Naive RAG**:
*   **Простота реалізації**: Легко налаштувати.
*   **Не потребує донавчання LLM**: Зберігає час та ресурси.
*   **Підвищена точність**: Використовує зовнішню інформацію для зменшення галюцинацій LLM.

**Обмеження**:
*   **Проблеми з фрагментацією інформації**: Важлива інформація може бути розділена між чанками, що ускладнює отримання повного контексту.
*   **Розбавлення семантичного значення**: Великі чанки можуть розбавляти семантичне значення, що погіршує якість пошуку.

## Sentence-Window Retrieval

Sentence-Window Retrieval — це вдосконалена техніка RAG, спрямована на подолання обмежень Naive RAG, особливо щодо фрагментації контексту та роз'яснення займенників.

**Як це працює**:
1.  **Вбудовування речення**: Вбудовування розраховуються для окремих речень.
2.  **Зберігання контексту вікна**: Крім вбудовування речення, зберігаються також навколишні речення (наприклад, одне речення до і два після) як "вікно контексту".
3.  **Пошук**: Під час запиту пошук за векторною схожістю відбувається на рівні окремих речень.
4.  **Подача повного контексту до LLM**: Після знаходження найбільш релевантного речення, *ціле вікно контексту* (речення, що відповідає запиту, плюс його навколишні речення) передається до LLM.

**Переваги Sentence-Window Retrieval**:
*   **Збереження семантичної цілісності**: Уникає розділення ключової інформації між частинами, оскільки пошук відбувається на рівні речень, а потім надається ширший контекст.
*   **Покращене розпізнавання посилань**: LLM отримує ширший контекст, що допомагає їй краще розуміти зв'язки між займенниками та сутностями (наприклад, "його" та місто, на яке воно посилається).
*   **Більш точне генерування відповідей**: Забезпечує LLM достатнім, але не надмірним контекстом, що призводить до більш точних та релевантних відповідей.

## Порівняльна таблиця

| Аспект                     | Naive RAG                                            | Sentence-Window Retrieval                                        |
| :------------------------- | :--------------------------------------------------- | :--------------------------------------------------------------- |
| **Розмір чанка для пошуку** | Фіксовані, часто більші чанки (наприклад, абзаци)    | Окремі речення (або інші невеликі одиниці)                     |
| **Вбудовування**           | Для великих чанків                                   | Для окремих речень                                             |
| **Контекст для LLM**       | Безпосередньо отримані чанки                         | Отримане речення + навколишнє "вікно" речень                  |
| **Обробка фрагментів**     | Схильний до фрагментації інформації                  | Краще справляється з фрагментацією та забезпеченням повного контексту |
| **Вирішення займенників**  | Обмежене, якщо займенник та його об'єкт знаходяться в різних чанках | Покращене, завдяки наданню ширшого вікна контексту             |
| **Складність**             | Простіший у реалізації                               | Складніший, але забезпечує кращу якість результатів               |
